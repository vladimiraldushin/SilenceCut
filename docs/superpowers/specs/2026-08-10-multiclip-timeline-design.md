# Мультиклиповый таймлайн: работа с разнородными исходниками

Дата: 2026-08-10

> **Пересмотрено 11.08.2026 — хранение проекта.** Решение «sidecar рядом с главным источником»
> ниже больше не действует. Проект стал самостоятельным документом `.silencecut` в произвольном
> месте: место спрашивается сразу после первого ролика, список проектов живёт на стартовом экране
> (`RecentProjectsStore` + `ProjectBrowserView`), автоматическая подцепка по пути видео убрана.
> Причина: с несколькими источниками непонятно, рядом с каким роликом лежит проект и что делать,
> если этот ролик убрали с таймлайна. Формат файла не менялся, старые sidecar-файлы открываются
> как обычные документы. Актуальное описание — в `AGENTS.md`.

## Задача

Сегодня SilenceCut работает с одним видеофайлом: импорт заменяет проект целиком, весь анализ
завязан на `project.sourceURL`, а `CompositionBuilder` берёт размер и ориентацию кадра у первого
клипа с прямым комментарием «all clips share same source».

Нужна полноценная работа с несколькими разнородными исходниками на одном таймлайне: несколько
роликов подряд, перебивки поверх речи, разные форматы кадра, разрешения, частоты кадров и
громкости.

## Решения, принятые на этапе обсуждения

| Вопрос | Решение |
|---|---|
| Как перебивка работает со звуком | Видео и звук раздельно: картинка перебивки перекрывает основное видео, звук основного продолжает идти |
| Разные форматы кадра | Ручной кадрировщик на клип: масштаб и сдвиг, рамка в превью |
| Платформы | macOS сейчас; iOS остаётся одноклиповым, но открывает мультиклиповые проекты на просмотр и экспорт |
| Хранение проекта | Sidecar рядом с главным (первым) источником, как сегодня, плюс «Сохранить как…» |
| Как ставится перебивка | Перетаскиванием на вторую дорожку таймлайна, с последующей тягой краёв |
| Нормализация громкости | На каждый источник свой гейн; общий `audioGain` остаётся мастером поверх |

## Архитектурный подход: основа + оверлеи

`EditTimeline` сохраняет `clips` как **хребет** — связанные видео и звук, по которым работают
вырезание пауз, риппл и субтитры. Рядом появляется `overlays` — видео без звука, приколотое к
диапазону таймлайна.

Отвергнутые варианты:

- **Настоящая многодорожечность** (`tracks: [Track]`). `timeline.clips` торчит по всему коду;
  радиус поражения несоразмерен задаче. Главное — как только звук перестаёт быть одним
  непрерывным потоком, «вырезать паузы» и субтитры теряют однозначность, и хребет приходится
  вводить обратно, но уже неявно.
- **Один массив с ролью у клипа**. Массив перестаёт быть последовательностью, и
  `recalculateOffsets`, `clipIndex(at:)`, `timelineTime(forSourceTime:)` обрастают условиями.

Выбранная модель оставляет дверь в многодорожечность открытой: `overlays` со временем становится
`tracks[1]`.

## Модель данных (RECore)

### Реестр источников

```swift
public struct MediaSource: Identifiable, Codable, Equatable {
    public let id: UUID
    public var url: URL
    public var bookmarkData: Data?          // security-scoped, переживает перезапуск
    public var duration: CMTime
    public var naturalSize: CGSize
    public var preferredTransform: CGAffineTransform
    public var nominalFrameRate: Double
    public var hasAudio: Bool
    public var integratedLUFS: Double?      // результат замера громкости, если был
    public var gain: Double                 // множитель громкости этого источника, 1.0 по умолчанию
}
```

`TimelineClip.sourceURL: URL` заменяется на `sourceID: MediaSource.ID`. Метаданные живут в одном
месте, поэтому `CompositionBuilder` перестаёт грузить `AVURLAsset` и ждать `load(.naturalSize)` на
каждом клипе.

Реестр лежит **внутри `EditTimeline`**, а не в `Project`:

```swift
public struct EditTimeline: Codable, Equatable {
    public var sources: [MediaSource]
    public var clips: [TimelineClip]
    public var overlays: [OverlayClip]
    public func source(for id: MediaSource.ID) -> MediaSource?
}
```

EDL остаётся самодостаточным: `CompositionBuilder.build(from:options:)`, `ExportService`,
`BatchQueue` и снимки undo по-прежнему принимают одну структуру, и ни одна сигнатура не обрастает
вторым параметром с реестром. Побочный выигрыш — `ProjectSnapshot` уже хранит `timeline`, так что
источники сохраняются без отдельного поля.

`Project.sourceURL` и `Project.sourceBookmarkData` удаляются; главный источник —
`timeline.sources.first`, к нему привязан sidecar.

### Кадрирование

```swift
public struct ClipFraming: Codable, Equatable {
    public var scale: Double = 1.0      // 1.0 = заполнить холст центральным кропом
    public var offset: CGPoint = .zero  // сдвиг в долях холста от центра
}
```

Без перечисления режимов: «Заполнить» — это `scale = 1`, «Вписать целиком» — кнопка, считающая
`scale = fitScale / fillScale`. При `scale < 1` края чёрные. Джамп-кат зум множится поверх.

Поле есть и у `TimelineClip`, и у `OverlayClip`.

### Хребет и перебивки

```swift
public struct OverlayClip: Identifiable, Codable, Equatable {
    public let id: UUID
    public let sourceID: MediaSource.ID
    public var sourceRange: CMTimeRange     // что берём из исходника
    public var timelineStart: CMTime        // куда кладём
    public var framing: ClipFraming
    public var isEnabled: Bool
    public var timelineRange: CMTimeRange { .init(start: timelineStart, duration: sourceRange.duration) }
}
```

Длительность выводится из `sourceRange`, отдельно не хранится — рассинхрону неоткуда взяться.

### Риппл

Все укорачивания таймлайна идут через одну операцию:

```swift
mutating func applyRemovals(_ removed: [CMTimeRange])  // диапазоны в СТАРОМ времени таймлайна
```

Правило для перебивки: целиком внутри удаляемого — исчезает; пересекается краем — обрезается
(вместе с `sourceRange`); целиком после — едет назад на суммарную длину вырезанного до неё.
Функция чистая, покрывается тестами без видеофайлов.

### Детекция пауз становится не разрушительной

Сегодня `applySilenceReview` собирает таймлайн заново через `EditTimeline.fromSpeechRanges` и
стирает любую ручную работу. Новая схема: детекция идёт **по каждому клипу хребта в его
собственных координатах**, режет внутри клипа и не трогает остальную раскладку.

```swift
public struct SilenceReviewZone: Identifiable, Equatable {
    public let id: UUID
    public let clipID: TimelineClip.ID
    public let sourceRange: CMTimeRange   // координаты исходника этого клипа
    public var willCut: Bool
}
```

Это заодно снимает неоднозначность: если один и тот же ролик стоит на таймлайне дважды, глобальный
маппинг «время исходника → время таймлайна» вернул бы первое попадание и соврал.
`EditTimeline.fromSpeechRanges` удаляется; вместо неё `splitClipBySpeechRanges(clipID:speechRanges:)`.

### Хранение

`ProjectSnapshot` получает `version: Int` (у старых файлов поля нет — читается как 1). Источники
приезжают внутри `timeline`, отдельного поля не нужно. Sidecar остаётся рядом с главным
источником — `<главное видео>.silencecut`. Поведение «кинул ролик, продолжил с того же места» не
меняется. Добавляется «Сохранить как…» в произвольное место.

Миграция v1 → v2 идёт в два шага, потому что старый клип знает URL, но не знает метаданных
исходника:

1. `TimelineClip.init(from:)` при отсутствии `sourceID` читает `sourceURL` и кладёт его в
   `legacySourceURL` — временное поле вне `Codable`-контракта.
2. `ProjectStore.load(for:)` при `version < 2` собирает `MediaSource` по каждому уникальному
   `legacySourceURL`, проставляет клипам `sourceID` и очищает временное поле. Метаданные
   (`naturalSize`, `preferredTransform`, `nominalFrameRate`, `hasAudio`) заполняются как заглушки и
   догружаются из `AVURLAsset` при импорте — `ProjectStore` синхронный и не может ждать ассет.

## Сборка композиции (RETimeline)

`CompositionBuilder.build(from:options:)` остаётся единственной точкой сборки: превью и экспорт
идут через неё, «что видно, то и получится» сохраняется.

### Дорожки

Три дорожки: видео хребта, видео перебивок, звук хребта. Перебивки на отдельной дорожке, а не
врезкой в хребет: сборщик не занимается нарезкой хребта вокруг каждой перебивки, и позже туда
ложатся полупрозрачность и PiP.

Инструкция видеокомпозиции одна на весь таймлайн, внутри два `layerInstruction`:

- **хребет** — `setTransform` в начале каждого клипа;
- **перебивки** — `setTransform` в начале каждой перебивки плюс `setOpacity` 1/0 на её границах.

Порядок слоёв в `layerInstructions` фиксируется эмпирически при реализации тестом на двух
фикстурах разного цвета: документация в этом месте неоднозначна.

### Кадр

```swift
renderTransform(sourceTransform:orientedSize:targetSize:framing:zoom:)
// scale = fillScale × framing.scale × zoom
// translate = центр + framing.offset × targetSize
```

Функция чистая, вся математика кадра проверяется без видеофайлов.

- Холст проекта — из `renderOptions.outputAspect`; для `.original` берётся ориентированный размер
  первого клипа хребта (задокументировать: при разнородных исходниках «оригинал» неочевиден).
- Ширина и высота округляются до чётных — H.264 не принимает нечётные.
- Частота кадров проекта — максимум по источникам хребта, зажатый в 24…60.

### Звук

1. **Клип без звука не ломает синхрон**: `insertEmptyTimeRange` на длину клипа. Раньше источник был
   один, и расхождению неоткуда было взяться.
2. **Фиксированный формат чтения**: `AVAssetReaderAudioMixOutput` создаётся с явным LPCM 48 кГц
   стерео вместо `audioSettings: nil` — иначе 48 кГц стерео и 44,1 кГц моно в одной дорожке
   разъедутся.
3. **Параметры AAC от проекта, а не от формата первой дорожки.**
4. **Гейн на источник**: пер-сегментные рампы в `audioMix` уже есть; `MediaSource.gain` умножается
   на общий `options.audioGain`.

Гейн хранится на самом источнике, а не словарём `[UUID: Double]` в `RenderOptions`: громкость —
свойство исходника, а не настройка рендера, и словарь с ключом-UUID превратился бы в JSON в
массив чередующихся ключей и значений.

## Анализ (REAudioAnalysis + вьюмодель)

Кеши анализа — на источник, а не на проект:

```swift
struct SourceAnalysis {
    var waveform: WaveformData
    var rms: RMSCache
}
// EditorViewModel: private var analyses: [MediaSource.ID: SourceAnalysis]
```

Анализ запускается при добавлении каждого источника и живёт только в памяти — на диск попадает
слишком много данных ради слишком малой экономии. Waveform на таймлайне рисуется по клипам: вью
получает словарь `[sourceID: WaveformData]` и нарезает по `sourceRange` клипа.

Замер громкости — по каждому источнику; `LoudnessAnalyzer.gain(for:targetLUFS:)` даёт гейн, а
результат замера и гейн сохраняются прямо в `MediaSource` (`integratedLUFS`, `gain`), поэтому
повторно замерять после открытия проекта не нужно.

## UI (REUI, macOS)

1. **Полка источников** над таймлайном: чипы добавленных роликов, кнопка «Добавить видео»
   (мультивыбор), дроп из Finder, статус анализа и громкости. Источник тянется с полки на дорожки.
2. **Таймлайн в две дорожки**: верхняя — перебивки, нижняя — хребет. Дроп из Finder и с полки,
   перетаскивание перебивки по горизонтали, тяга краёв, магниты к границам клипов хребта и к
   плейхеду.
3. **Кадрировщик**: у выделенного клипа поверх превью рамка — драг сдвигает, скролл масштабирует;
   кнопки «Заполнить», «Вписать», «Сбросить».
4. **Добавление в хребет**: «Добавить видео» кладёт в конец; дроп на нижнюю дорожку вставляет в
   позицию с рипплом.

`NSOpenPanel` в трёх местах переводится на `allowsMultipleSelection = true`
(`SilenceCutApp.swift:152`, `:161`, `MainEditorView.swift:263`).

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Файл источника не найден при открытии проекта | Источник помечается offline, его клипы на таймлайне штрихуются, экспорт блокируется с явным сообщением и предложением «Найти файл…» |
| Файл без видеодорожки | Отклоняется при добавлении с сообщением |
| Источник без звука | `insertEmptyTimeRange`, синхронизация сохраняется |
| Не удалось вставить сегмент в композицию | Клип помечается несовместимым, остальной таймлайн собирается |
| Ошибка или отмена анализа источника | Источник остаётся без кешей, детекция пауз по нему недоступна; проект работает |
| Перебивка выходит за конец хребта | Обрезается по длине хребта при сборке |

## Тестирование

`RECoreTests`:

- миграция sidecar v1 → v2: клипы получают `sourceID` синтезированного источника;
- `applyRemovals`: перебивка внутри выреза, на краю, после выреза, полностью до;
- `splitClipBySpeechRanges` не трогает соседние клипы и перебивки вне клипа;
- маппинг времени по клипам хребта с несколькими источниками;
- `EditTimeline` с несколькими источниками и перебивками сериализуется и читается обратно.

`RETimelineTests`:

- `renderTransform` с кадрированием: заполнить, вписать, сдвиг, комбинация с джамп-кат зумом;
- округление холста до чётных;
- частота кадров проекта как максимум по источникам.

`REAudioAnalysisTests`:

- гейн на источник считается независимо для двух разных замеров.

Интеграционный тест сборки композиции из двух источников разного размера — на коротких фикстурах,
сгенерированных `AVAssetWriter` в `setUp`. Он же фиксирует порядок слоёв `layerInstructions`.

## Этапы реализации

1. Модель RECore: `MediaSource`, `ClipFraming`, `sourceID`, `overlays`, `applyRemovals`,
   `ProjectSnapshot` v2 с миграцией. Тесты.
2. `CompositionBuilder`: пер-клиповые трансформации, кадрирование, дорожка перебивок, пустые
   аудиодиапазоны. Тесты математики.
3. `ExportService`: фиксированный формат чтения звука, параметры AAC от проекта.
4. `EditorViewModel`: реестр источников, добавление роликов, пер-клиповая детекция пауз,
   пер-источниковые кеши и громкость, автосохранение v2.
5. Таймлайн macOS: две дорожки, дроп, перетаскивание и тяга перебивок.
6. Кадрировщик в превью.
7. Полка источников, мультивыбор в панелях, «Сохранить как…», offline-источники.
8. iOS: собирается, открывает мультиклиповые проекты на просмотр и экспорт.

## Вне объёма

- Звук у перебивок, музыка, войсовер, третий и последующие слои.
- Переходы между клипами.
- Полноценная многодорожечность (`tracks: [Track]`).
- Мультиклиповое редактирование на iOS.
